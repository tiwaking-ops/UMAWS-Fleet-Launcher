# PMK Task Management

## Critical
- **I2 Invariant**: NEVER write directly to the `.pm/` directory or its subdirectories. All state changes MUST go through the `pmk` CLI or `pmk.api`.
- **I5 Invariant**: Every task MUST have a `gate_cmd` (oracle). A task cannot reach `DONE` status without a passing gate command and an evidence bundle.
- **Goal Reference**: Every task must be linked to an existing Goal ID from the ledger.
- **Windows Compatibility**: Use `utf-8-sig` when reading human-authored task descriptions or acceptance criteria from files.

## Instructions

1. **Verify Environment and Target Goal**
   - Ensure the project is installed in editable mode: `pip list` should show `pmk` pointing to `src/pmk`.
   - Retrieve the current list of goals: `pmk list --goals` or inspect `.pm/views/ledger.json`.
   - **Validation**: Confirm the `goal_ref` exists. If the user hasn't specified a goal, list active goals and ask for clarification.

2. **Define Task Scope and Acceptance**
   - Identify the specific files that will be modified (`scope.write`). Use relative paths from the project root.
   - Formulate a specific `gate_cmd`. For this project, this is usually a `pytest` command (e.g., `pytest tests/fleet/test_dispatcher.py`).
   - **Validation**: Verify that the files in the scope actually exist or are planned new files.

3. **Create the Task via PMK CLI**
   - Use the `pmk task add` command (or the specific CLI pattern defined in `src/pmk/cli.py`).
   - Pattern: `pmk task add --goal <GOAL_ID> --name "<TITLE>" --scope "path/to/file1,path/to/file2" --gate "pytest <TEST_PATH>"`.
   - If acceptance criteria are lengthy, pass them via a temporary file or the `--description` flag.

4. **Verify Task Injection**
   - Run `pmk list --tasks` to ensure the new task appears in the `PENDING` or `TODO` state.
   - Check `.pm/views/queue.json` to verify the projection has updated correctly.
   - **Validation**: The Task ID generated by the Kernel must be captured for future reference.

5. **Link Evidence (If completing)**
   - If the task is being updated to `DONE`, ensure the `gate_cmd` has been run and the output is redirected to `.pm/evidence/<TASK_ID>.txt` via the `pmk task submit` command.

## Examples

### User says: "Add a task to implement the heartbeat logic in the Fleet Dispatcher for Goal G-102"

**Actions taken:**
1. Run `pmk list --goals` to verify `G-102` exists.
2. Identify scope: `src/fleet/dispatcher.py`.
3. Identify gate: `pytest tests/fleet/test_heartbeat.py`.
4. Execute: `pmk task add --goal G-102 --name "Implement Heartbeat Logic" --scope "src/fleet/dispatcher.py" --gate "pytest tests/fleet/test_heartbeat.py"`.
5. Confirm: `Task T-504 created and linked to G-102.`

**Result:**
A new task event is appended to `.pm/events/` via the Kernel, and `.pm/views/queue.json` reflects the new task.

## Common Issues

- **Error: 'pmk' is not recognized as an internal or external command**
  - **Fix**: The virtual environment is not active or `pip install -e .` was not run. Run `.\.venv\Scripts\activate` and `pip install -e .`.
- **Error: Goal ID 'G-XXX' not found**
  - **Fix**: Check `.pm/views/ledger.json` for the exact ID. Ensure the goal is not in a `CANCELLED` or `CLOSED` state.
- **Error: Permission denied on .pm/events/log.jsonl**
  - **Fix**: Another process (like a hanging `pmk` call or the Console) might have a lock. On Windows, check for existing python processes or `.lock` files in `.pm/` using `src/pmk/plat.py` patterns.
- **Gate Command Fails Immediately**
  - **Fix**: Ensure the `gate_cmd` uses the correct python interpreter. Use `python -m pytest` instead of just `pytest` if the pathing is ambiguous.
